# UI and Menus

The HUD, main menu and escape menu: UI Toolkit trees built in C#, each on its own panel with its own stylesheet stack. The [debug menu](debug-menu.md) is separate and uses Dear ImGui.

---

## Panels and Surfaces

[UiSurface.cs](../Assets/Scripts/Piper/UI/UiSurface.cs) names the surfaces. Each surface renders through a `UiPanel` ([UiPanel.cs](../Assets/Scripts/Piper/UI/UiPanel.cs)), which creates a child GameObject with a `UIDocument` and exposes a full-screen `content` element. Controllers build into `content` immediately and the panel attaches it to the document root, so a build never waits for the document to initialise. Stylesheets go on the document root so `:root` token rules match.

| Surface | Sort order | Controller |
|---|---|---|
| `Hud` | 0 | `GameHud` |
| `MainMenu` | 20 | `MainMenu` |
| `EscapeMenu` | 30 | `EscapeMenu` |

All panels share `Assets/UI/PipePanelSettings.asset`, held by `ScreenUIHolder` on the `UI` object: scale with screen size from a 1920x1080 reference, matching height, with the default runtime theme.

**The `UI` object needs an `EventSystem` with an `InputSystemUIInputModule`** or no panel receives pointer or navigation events; [PiperSetup.cs](../Assets/Editor/PiperSetup.cs) adds both.

## Skins

A `UiSkin` ([UiSkin.cs](../Assets/Scripts/Piper/UI/UiSkin.cs)) is a `ScriptableObject` with a surface and an ordered `StyleSheet[]`; a later sheet wins at equal specificity. `UiSkins.Register` applies `Resources/UiSkins/{Surface}Default.asset` to a panel. `PiperSetup.BuildUiAssets` creates the three skins and the panel settings, so they are regenerated by `-Setup`.

| Surface | Sheets, in order |
|---|---|
| `Hud` | theme, elements, hud, tooltips |
| `MainMenu` | theme, menu-components, menu-main, menu-pipeworld |
| `EscapeMenu` | theme, menu-components, menu-escape |

The sheets are in `Assets/UI/default/`. `menu-pipeworld.uss` darkens the main menu over the live world and lightens its logo. Fonts, crosshair sprites and key glyphs the sheets name with `resource(...)` are under `Assets/Resources/`. **Class selectors beat type selectors regardless of file order,** so an override of a rule written against a class must use a class too.

`UiSettings.NotifyChanged` raises `Changed`; `GameHud` listens and toggles the `hud-font-normal` class from `Settings.hudFontSize`, which switches the font-size tokens.

## HUD

[HudRegions.cs](../Assets/Scripts/Piper/UI/HudRegions.cs) builds named empty regions (corners, centres, full-height sides and a crosshair row). [GameHud.cs](../Assets/Scripts/Piper/UI/GameHud.cs) fills them in `Setup` and updates them in `doUpdate`; nothing is rebuilt per frame, only text, classes and display.

| Element | Region | Source |
|---|---|---|
| `CrosshairElement` | Crosshair row, centre | `SetCrosshairStyle`, `SetCrosshairProgress` |
| `InteractionPromptElement` x3 | Crosshair row, left | Left click, right click and scroll prompts: `ChangeLeftClickPrompt` and siblings. An empty string hides a prompt |
| `TooltipManagerElement` | Crosshair row, right | [interaction-modes.md](interaction-modes.md#tooltips) |
| `InventoryListElement` | Full-height left | One `InventoryItemElement` per seen item, flashing on change |
| Mode label | Bottom centre | `ChangeModeText` |
| Network status | Bottom right | `PiperGame.describeNetworkStatus` |

`SetGameplayHudVisible` shows or hides the gameplay elements; the main menu hides them. Elements are `VisualElement` subclasses with a parameterless constructor and a `UxmlFactory`, building their children in the constructor and exposing properties and methods that mutate them.

## Menus

Both menus build a full-screen `.menu` overlay and follow the same rules.

- **Menu state is reference counted.** `SetMenuState(true)` on a menu calls `PlayerController.SetMenuState(true)`, which unlocks the cursor and stops look and movement; closing calls it with false. A menu opened over another never relocks the cursor when the first closes, and the [debug menu](debug-menu.md#cursor-and-input) uses the same counter.
- **Every button goes through the controller's button helper,** so it lands in `allButtons`. `NavigationMoveEvent` cycles focus through that list for keyboard and gamepad; a button outside it is unreachable.
- **Panels slide with USS only.** `MenuViewPanel.Show` and `Hide` toggle the `visible` class; the transition lives in `menu-components.uss`. The panel opened from a button disables every other button until it is closed, and the button reads "Back" meanwhile.
- **State that can change while open is recomputed in `doUpdate`,** such as which hosting buttons show. A panel whose backing state disappears is closed.

[MainMenu.cs](../Assets/Scripts/Piper/UI/MainMenu.cs) shows while `PiperGame.mainMenuMode` is true: New Game, Continue (hidden unless the newest save is compatible), Load Game, Join Game, Settings and Quit. [EscapeMenu.cs](../Assets/Scripts/Piper/UI/EscapeMenu.cs) toggles on Escape while playing: Resume, Save Game, Load Game, Settings, Begin Hosting or End Hosting, Quit to Menu and Quit to Desktop, with a mode readout. Escape closes an open panel before it closes the menu.

Menu choices go through `IMenuActions` ([MenuActions.cs](../Assets/Scripts/Piper/UI/MenuActions.cs)), whose game implementation queues deferred operations on `PiperGame` ([piper-systems.md](piper-systems.md#game-flow)).

| Panel | Contents |
|---|---|
| `LoadGamePanel` | Saves newest first with playtime and prop count; saves of another version cannot be loaded |
| `JoinGamePanel` | A direct-connect address field; the last address is remembered |
| `SettingsPanel` | Audio (master volume), Graphics (vsync, field of view), Interface (font size), Controls (mouse sensitivity, player name); every change saves immediately |
