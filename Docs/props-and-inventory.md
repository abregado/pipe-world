# Props and Inventory

The world's placeable objects and the items the players carry: how they are stored, how they appear in the scene, and which exist. To add one, see [adding-a-prop.md](adding-a-prop.md).

---

## World Storage

The `World` ([World.cs](../Assets/Scripts/Piper/Systems/World.cs)) holds a `PropAllocator`, a slab of unmanaged `Prop` structs in native memory, and a `WorldData` with the tick, the player list and the `Inventory`. A `Prop` is a slab header, a `PropPrototypeId`, a position, a rotation and a `PropExtraData` union ([SystemTypes.cs](../Assets/Scripts/Piper/Systems/SystemTypes.cs)).

**A free slot is zeroed, so `slabHeader.allocated` is the only reliable liveness test, and a `PropHandle` stays valid only while its generation matches.** Use `world.tryGet(handle)` whenever the prop may have been deleted; `get` asserts.

`World.save()` writes a header (magic and `Constants.saveVersion`), the raw `WorldData`, then each slab part with its length. `World.load` reads it back. **Adding or reordering a field in `WorldData` or `Prop` changes the layout, so bump `saveVersion`;** the load panel lists saves of other versions as incompatible.

## Prop Prototypes

[PropPrototypes.cs](../Assets/Scripts/Piper/Systems/PropPrototypes.cs) holds the `PropPrototypeId` enum and a `PropPrototype` per id: display name, description, the inventory item that places it, its cost and its prefab. `PropPrototypes.instance` loads each prefab from `Resources/PropPrefabs/<id>.prefab` at startup and asserts the prefab's `PropBehaviour` declares the same id.

| Prop | `PropExtraData` | Behaviour |
|---|---|---|
| `CollectableGeneric` | `collectable`: item and amount | Interact to take the item; the prop is deleted |
| `DoorSingleItem` | `door`: open flag, required item | Interact to open or close; a required item is spent opening |
| `PlaceableLamp` | `lamp`: on flag | Interact to switch; placed from a `LightUnit` item |
| `RefreshableBox` | `refreshable`: stored amount, next refill tick | Hold to take everything; refills one unit every five seconds |

[PropLogic.cs](../Assets/Scripts/Piper/Systems/PropLogic.cs) sets each prop's initial data, advances time-based state in `update`, and implements the world changes the actions call. The box's `nextRefreshTick` is `ulong.MaxValue` while full, not `0`: `0` is a valid tick and would refill it immediately.

## Inventory Items

[InventoryItemPrototypes.cs](../Assets/Scripts/Piper/Systems/InventoryItemPrototypes.cs) defines `InventoryItemPrototypeId` and a prototype per id: name, category, description, a HUD colour and the prop it places (`placedBuildingId`, set when a `PropPrototype` names the item).

`Inventory` is a fixed array of counts plus a `seen` bit per item. `setCount` sets `seen` once a count is positive, and the HUD lists exactly the seen items, so an item stays listed at zero after its first pickup.

## Views

[PropSyncer.cs](../Assets/Scripts/Piper/Core/PropSyncer.cs) keeps one pooled `PropBehaviour` GameObject for every allocated prop within `SystemSync.FADEIN_DISTANCE` of the player and recycles it beyond `FADEOUT_DISTANCE`. A view is keyed by prototype, position and rotation, not by handle, so it survives a world reload that reproduces the same prop. A view that moved in the world is recycled and re-created.

[PropBehaviour.cs](../Assets/Scripts/Piper/Props/PropBehaviour.cs) is the base view. It reads its `Prop` through `propHandle`, exposes `resetVisualisation` (run each time a pooled view is bound to a prop) and `updateVisualisation` (every frame), and implements highlighting and tooltips. **Highlighting works by writing `_Tint` through a `MaterialPropertyBlock`, so a prop's material must use the `PipeWorld/Scatter` shader.** Per-instance colour, such as a collectable's item colour, goes through `SetBaseTint` for the same reason.

Prefabs are placeholders built by [PiperSetup.cs](../Assets/Editor/PiperSetup.cs) from flat-shaded boxes with vertex colours, with the alpha channel marking glow. They are regenerated by every `-Setup`. A collider that must be interactable carries `IInteractablePassthrough` and `TooltipPassthrough` pointing at the prop's root when it is on a child object (the door's posts and panel); a collider on the root needs neither.

## Placement

There is no placement tool. Props enter the world through the `PlaceProp` and `PlacePropUsingItem` actions, from [PiperGame.SeedWorld](../Assets/Scripts/Piper/Core/PiperGame.cs) and from the Piper section of the [debug menu](debug-menu.md#piper-section). `PlacePropUsingItem` spends one of the prototype's `itemId` and refuses when the player has none.
